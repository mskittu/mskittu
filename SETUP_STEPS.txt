==========================================================================
 SOURCE TARGET RECON  -  SETUP STEPS
 Implemented by the Impairments Data Engineering Team (Harleen, Kushal)
==========================================================================

What you get
------------
A team website at https://recon.<your-domain> where everyone signs in with
their own account and uses 6 tools:
  1. Compare records   (source vs target files, TRUE/FALSE per column)
  2. Statistics        (sum, mean, median, min, max ... source vs target)
  3. Data quality      (null checks, duplicate checks)
  4. Code compare      (SQL / HQL / PySpark side by side)
  5. DDL compare       (CREATE TABLE statements)
  6. JSON compare
plus TEAM HISTORY: every run is saved under the name of the person who ran
it, anyone signed in can open it and download the Excel report, and runs are
deleted automatically after 7 days.

Files are compared inside each user's browser. Only the result summary and
the Excel report are stored on the server.


--------------------------------------------------------------------------
 PART A.  BEFORE YOU START  (get these ready)
--------------------------------------------------------------------------
[ ] A server: Linux VM (RHEL 8/9 or Ubuntu 22.04+) recommended,
    or Windows Server 2019+.  2 CPU, 4 GB RAM, 20 GB disk.
[ ] Python 3.9 or newer on the server.
[ ] A DNS name for the site, e.g.  recon.<your-domain>
[ ] An HTTPS certificate + key for that name (from your internal CA).
[ ] Port 443 open from the office network to the server.
[ ] Info-security approval (reports can contain row-level data, and
    everyone signed in can download every report in Team history).
[ ] The file  recon_app.zip


--------------------------------------------------------------------------
 PART B.  ONE FILE TO ADD:  the Excel library  (required)
--------------------------------------------------------------------------
The website needs one JavaScript file to build the coloured Excel reports.

Option 1 - from any PC with internet:
    Open this link and save the file:
      https://cdn.jsdelivr.net/npm/xlsx-js-style@1.2.0/dist/xlsx.bundle.js
    Put it here:   recon_app/static/xlsx.bundle.js

Option 2 - through your company npm mirror (Artifactory / Nexus):
    npm pack xlsx-js-style@1.2.0
    tar -xzf xlsx-js-style-1.2.0.tgz package/dist/xlsx.bundle.js
    copy package/dist/xlsx.bundle.js  to  recon_app/static/xlsx.bundle.js

If this file is missing, the site still works but shows a red banner and
Excel downloads are switched off.

--------------------------------------------------------------------------
 PART D.  LIVE SETUP ON A LINUX SERVER  (recommended)
--------------------------------------------------------------------------
Run these as a user with sudo rights.

STEP 1 - Create the service user and folders
    sudo useradd --system --home /opt/recon --shell /sbin/nologin recon
    sudo mkdir -p /opt/recon/app /opt/recon/data /opt/recon/backups

STEP 2 - Copy the app to the server
    (copy recon_app.zip to the server first, e.g. with WinSCP or scp)
    unzip recon_app.zip
    sudo cp -r recon_app/. /opt/recon/app/
    cd /opt/recon/app
    ls static/xlsx.bundle.js        <- must exist (Part B)

STEP 3 - Install Python packages
    sudo python3 -m venv .venv
    sudo .venv/bin/pip install -r requirements.txt
    (behind a company mirror, add:
     --index-url https://<your-artifactory>/api/pypi/pypi/simple )

STEP 4 - Create the settings file
    python3 -c "import secrets; print(secrets.token_hex(32))"
        -> copy the long string it prints
    sudo cp .env.example .env
    sudo vi .env
    Set these lines:
        RECON_SECRET_KEY=<paste the long string>
        RECON_ADMIN_USER=admin
        RECON_ADMIN_PASSWORD=<strong temporary password>
        RECON_DATA_DIR=/opt/recon/data
        RECON_HTTPS=1
        RECON_BEHIND_PROXY=1
        RECON_RETENTION_DAYS=7
    Save, then:
    sudo chown -R recon:recon /opt/recon
    sudo chmod 600 /opt/recon/app/.env

STEP 5 - Test run
    sudo -u recon /opt/recon/app/.venv/bin/waitress-serve --host 127.0.0.1 --port 8080 app:app
    In a second window:
    curl http://127.0.0.1:8080/healthz
        -> should print  {"status":"ok"}
    Press Ctrl+C in the first window to stop.

STEP 6 - Start it as a service (starts on boot, restarts on failure)
    sudo cp /opt/recon/app/deploy/recon.service /etc/systemd/system/
    sudo systemctl daemon-reload
    sudo systemctl enable --now recon
    sudo systemctl status recon          <- should say "active (running)"

STEP 7 - HTTPS with nginx
    sudo dnf install nginx               (Ubuntu: sudo apt install nginx)
    sudo cp /opt/recon/app/deploy/nginx.conf /etc/nginx/conf.d/recon.conf
    sudo vi /etc/nginx/conf.d/recon.conf
        change:  server_name recon.your-company.internal;   (2 places)
        change:  ssl_certificate      /path/to/your.crt;
                 ssl_certificate_key  /path/to/your.key;
    sudo nginx -t
    sudo systemctl enable --now nginx
    sudo systemctl reload nginx
    RHEL only:
    sudo setsebool -P httpd_can_network_connect 1
    sudo firewall-cmd --permanent --add-service=https
    sudo firewall-cmd --reload

STEP 8 - Nightly backup
    sudo dnf install sqlite              (Ubuntu: sudo apt install sqlite3)
    sudo crontab -u recon -e
    add this line:
    30 2 * * * /opt/recon/app/deploy/backup.sh >> /opt/recon/backups/backup.log 2>&1

STEP 9 - Open the site
    https://recon.<your-domain>
    Sign in as admin with the password from .env.
    You will be asked to choose a new password.
    Then remove RECON_ADMIN_PASSWORD from .env (no longer needed).


--------------------------------------------------------------------------
 PART E.  LIVE SETUP ON WINDOWS SERVER  (alternative to Part D)
--------------------------------------------------------------------------
STEP 1  Install Python 3.12 (tick "Add python.exe to PATH").
STEP 2  Unzip to  D:\Recon\app  and add static\xlsx.bundle.js (Part B).
STEP 3  Open Command Prompt:
            cd /d D:\Recon\app
            py -m venv .venv
            .venv\Scripts\pip install -r requirements.txt
            copy .env.example .env
            notepad .env
        Set RECON_SECRET_KEY, RECON_ADMIN_PASSWORD and
            RECON_DATA_DIR=D:\Recon\data
STEP 4  Test: double-click  deploy\run_windows.bat
        then open  http://localhost:8080/healthz  -> {"status":"ok"}
STEP 5  Run as a Windows service with NSSM (https://nssm.cc):
            nssm install Recon "D:\Recon\app\.venv\Scripts\waitress-serve.exe" --host 127.0.0.1 --port 8080 --threads 8 app:app
            nssm set Recon AppDirectory "D:\Recon\app"
            nssm start Recon
STEP 6  HTTPS in IIS: install "URL Rewrite" and "Application Request
        Routing". Add an HTTPS binding with your certificate, and a
        Reverse Proxy rule to  http://127.0.0.1:8080
        In .env set RECON_HTTPS=1 and RECON_BEHIND_PROXY=1, then
        restart the service:  nssm restart Recon
STEP 7  Backup: Task Scheduler, nightly copy of D:\Recon\data

--------------------------------------------------------------------------
 PART H.  DAY-TO-DAY COMMANDS  (Linux)
--------------------------------------------------------------------------
Status ............ sudo systemctl status recon
Restart ........... sudo systemctl restart recon
Live logs ......... journalctl -u recon -f
Health ............ curl https://recon.<your-domain>/healthz
Reset a password .. sudo -u recon /opt/recon/app/.venv/bin/python /opt/recon/app/app.py reset-password <username>
Delete old runs now sudo -u recon /opt/recon/app/.venv/bin/python /opt/recon/app/app.py purge
                    (also happens automatically every hour)
Keep runs longer .. set RECON_RETENTION_DAYS=<days> in .env, then restart
Disable a leaver .. Admin tab -> Disable
Sign everyone out . change RECON_SECRET_KEY in .env, then restart

Update to a new version:
    1. Run deploy/backup.sh
    2. Copy the new files over /opt/recon/app  (KEEP .env and the data folder)
    3. sudo /opt/recon/app/.venv/bin/pip install -r /opt/recon/app/requirements.txt
    4. sudo chown -R recon:recon /opt/recon && sudo systemctl restart recon


--------------------------------------------------------------------------
 PART I.  IF SOMETHING GOES WRONG
--------------------------------------------------------------------------
Red banner "Excel downloads are switched off"
    -> static/xlsx.bundle.js is missing (Part B)

Signed in, then immediately signed out again
    -> site is on http:// but RECON_HTTPS=1. Use https://, or set
       RECON_HTTPS=0 only for a trial.

"Your session expired. Reload the page"
    -> reload; if it keeps happening, same fix as above.

502 Bad Gateway
    -> service not running:  sudo systemctl status recon
    -> RHEL SELinux:  sudo setsebool -P httpd_can_network_connect 1

"The report is too large to save"
    -> raise RECON_MAX_UPLOAD_MB in .env AND client_max_body_size in
       nginx.conf (same number), restart both.

"Too many failed attempts"
    -> wait 5 minutes, or an admin resets the password.

Lost the admin password
    -> app.py reset-password admin   (see Part H)

Everyone shows the same IP in the activity log
    -> set RECON_BEHIND_PROXY=1 in .env and restart.
